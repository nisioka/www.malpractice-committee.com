## 対応済み（2026-11, ブランチ fix/weekly-update-review-backlog）

週次更新の PR（#3・#11・#13〜#19・#23・#24）のレビューで、定型部分や生成スクリプトに原因があるため
「週次の記事追加の範囲外」として見送られてきた指摘を直した。生成側を直し、既存ページは
`_automation/fix_shared_markup.py`（冪等）と各生成スクリプトの再実行で揃えた。

- ✅ **共有ボタンが動かない**（PR #23・#24）: 共有欄の Twitter / Facebook が WordPress 用の
  `<記事URL>?share=twitter` を指しており、静的配信では記事が開き直すだけだった。各サービスの共有画面
  （`twitter.com/intent/tweet?text=<見出し>&url=<記事URL>`、`facebook.com/sharer/sharer.php?u=<記事URL>`）を
  直接指す。各862件。`sharing.min.js` は href に `share=` を含むリンクにしか手を出さないので干渉しない。
- ✅ **`<body>` の `itemschope`**（PR #3）: 綴りを `itemscope` に。542ファイル。
- ✅ **JSON-LD のパンくず先頭が「家」**（PR #3）: 画面のパンくずと同じ「ホーム」に。247ファイル。
- ✅ **`id="fb-root"` の重複**（PR #3）: 記事末の「SNSでもご購読できます。」欄の2つ目を外した。498ファイル。
- ✅ **一覧カードの画像リンクに名前が無い**（PR #11・#17）: アイキャッチが画像だけのリンクで alt が空
  だった。alt にカードの見出しを入れる。283件。記事ページの画像（リンクではない）は飾りなので空のまま。
- ✅ **カテゴリページの再生成で病院ページが旧形式に置き換わる**（PR #23 ほか）: `build_category.py` は
  ページをまるごと作り直していたため、基本情報・地図・関連記事カードの病院ページが日付＋タイトルだけの
  一覧になっていた。病院ページと WordPress 由来の一覧は作り直さず、新記事のカードを差し込むようにした。
  置き換わったままだった chuo-kcho・nishi-kcho・kyoto-u・osaka-metro-u は置き換わる直前の版から戻し、
  その後の全ページ修正のスクリプトを掛け直してから、後で加わった記事のカードを足した。
- ✅ **カテゴリページの閲覧が記事の閲覧として数えられる**（PR #23）: 生成したカテゴリページの footer が
  Jetpack の統計に最新記事の ID を渡していた。WordPress のカテゴリページと同じ 0 にした（10ページ）。
- ✅ **同じ週に足した記事が一覧で古い順に並ぶ**（PR #13・#15・#17）: `rebuild_listings.py` は新規カードを
  入力 JSON の並びで入れていた。カード全体を公開日時の新しい順に安定ソートする。過去に逆順で入った
  2組（post-1080/1081、post-1077/1078）も並び直した。
- 実体の無いサイト内参照は 3,246 件から 3,126 件になった。減った 120 件は、記事ページが無い記事の一覧
  カードにあった共有ボタンで、共有画面への直リンクに変わりサイト内参照ではなくなった分。記事ページが
  無いこと自体は変わっていない（下記「未対応」）。
- 既に直っていた指摘: サイドバーの検索欄の `aria-label`（PR #13・#15・#16・#19。#21 の検索欄で付いた）、
  サイドバーの関連書籍 `iframe` の `title`（PR #13・#16。#20 で枠ごと外した）、ヘッダーの Facebook
  リンクの `</a>` 欠落（PR #11。#12 で修正）、入れ子の `<article>` でカードの末尾が別の位置に漏れる問題
  （PR #3・#11・#13・#14・#15。#15 の `find_cards()` で修正）、メール共有の本文だけ旧ドメインになる問題
  （PR #3。#5 で修正）。
- 直さなかった指摘のうち、指摘そのものが当たらないもの: page/11・12 が更新されていない（PR #3。元サイト
  由来の欠番で、ページは存在しない）、カテゴリページのインデント（PR #3。表示に影響しない）。
